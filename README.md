# 音频转字幕（阿里云百炼）

上传音频/视频，调用阿里云百炼的 **Fun-ASR 离线识别**模型转成文字，**只支持普通话（中文）**。
Web 界面，本地运行；**识别与字幕导出分离**：音频只识别一次，之后可按场景档位反复导出 SRT / TXT 字幕。

## 功能

- 拖拽上传音频（mp3 / wav / m4a / flac / ogg / aac …）或视频（mp4 / mkv / mov …），上限 1GB
- 固定使用 Fun-ASR 非实时（离线）识别模型，音频统一按普通话识别
- 识别/导出分离：识别完成后分段登记进资产库，之后可反复导出多版字幕；导出全部是本地确定性计算，
  不调用 LLM，也没有按次计费
- 导入识别结果：可把已保存的中间产物（`segments.json`）直接导入 UI，免重复识别；
  也可以在资产库里直接挑一条识别结果反复导出，同样不重复识别
- **资产库**：音频、识别结果、字幕都登记为可复用资产（`assets/`），
  列表里能看到每条的“由来”（普通话 · 模型 · 断句档位），
  字幕可原地预览：顺资产链找到对应音频，点字幕条即跳转播放、播放时高亮跟随。
  （为此 `/api/assets/{id}/file` 自己实现了 Range：浏览器只在响应带 206 / `Accept-Ranges`
  时才会给出 `seekable` 区间，否则给它设 `currentTime` 会被静默忽略）
- 只服务本机：所有请求都要求 Host 是 `127.0.0.1` / `localhost`（挡 DNS rebinding），
  写操作再校验同源（挡 CSRF）
- **四个场景档位**，不再要求用户理解规则/LLM，也不需要填写字数：
  - **按标点**：完全按 ASR 标点直断，每个小句一条，不做长度优化
  - **默认**：大多数视频；每条约 15 字，优先保留完整意群，短句可合并，长句才切开
  - **频繁**：短视频；每条约 10 字，切得更勤，单条最多 15 字
  - **沉浸**：访谈、播客、知识内容；每条约 20 字，尽量少跳字，单条最多 30 字
- 三个节奏档共用**同一个确定性排版引擎**，只换目标字数、时长和阅读速度参数；
  没有“规则/LLM”两套实现，也没有按结果调参的分支

## 快速开始

1. 配置环境变量 `DASHSCOPE_API_KEY`（阿里云百炼 · 北京地域的 API Key）
2. 双击项目根目录的 **`本地中文字幕王.bat`**（桌面上有同名快捷方式，
   丢了就运行 `python scripts/make_shortcut.py` 重新生成）：
   自动检查环境、首次自动装依赖、启动服务并打开浏览器；
   关闭控制台窗口即停止服务，再次双击即重新启动（服务已在运行时双击只会打开页面）
3. 或者手动启动：

```powershell
pip install -r requirements.txt
python scripts/serve.py          # 推荐：自动选端口 + 就绪后打开浏览器
# 或直接指定端口
uvicorn app.main:app --port 18080
```

> **默认端口是 18080，不是 8000。** 同一台机器上的 Applio Desktop 硬编码占用
> `127.0.0.1:8000`（API）和 `127.0.0.1:3000`（界面），本项目用 8000 会与它撞车、
> 两者无法同时启动，所以整体挪到 18080——这个端口在 TCP 动态范围与 Windows 默认范围之外，
> 不会被 WinNAT 的保留区占用。**不要改回 8000 或 3000。**
>
> 端口仍然不是完全写死的：Windows（Hyper-V / WSL / Docker）会动态保留一段 TCP 端口，
> 万一首选端口落进保留区，绑定会报 `WinError 10013`，浏览器只能显示"无法访问"，
> 而 `netstat` 里看不到任何占用。`scripts/serve.py` 会依次尝试
> 18080 → 18081 → 18088 → 18090 → 28080，都不行就交给系统分配，并把实际地址
> 打印在窗口里、记到 `.runtime/server.json`（再次双击时按它找到已在运行的实例）。
> 想查当前保留区：`netsh interface ipv4 show excludedportrange protocol=tcp`。

> 服务只接受来自本机（`127.0.0.1` / `localhost`）的请求。用 `--host 0.0.0.0` 对外暴露
> 会一律返回 403——这道校验是挡 DNS rebinding 的，别为了局域网访问把它关掉。

## 识别的模型

只保留 `fun-asr`，界面上不再提供模型选择。

实测对比后确认 Fun-ASR 更适合本项目的普通话素材：专有名词与医生称谓更稳，输出不计费也更容易预估成本。
Qwen-Audio-3.1 虽然在方言和说话人分离上更强、Token 计费约便宜 10 倍，但在干净普通话抽查中没有准确度优势，
因此不纳入本工具。

价格：`fun-asr` 按音频时长 `0.00022 元/秒` 计费，约 **0.79 元/小时**，输出不计费；
华北2（北京）有 36,000 秒免费额度。

## 断句设计：先约束，再优化

不是“先看某段素材效果，再加一条规则”，而是从字幕的物理与认知约束出发：

1. **不可切**：切点只能落在 token 边界；不跨句末标点与长静音；不在引语内部断开；
   不拆“的/地/得”及其中心语、不拆数量词、不拆成对符号。
2. **读得完**：单条有最短/最长显示时长和每秒字数（CPS）上限；太短会闪，太长会滞留。
3. **读得顺**：优先在标点或 ASR 句段边界收束；避免以虚词、连接词、量词开头或结尾。
4. **意群完整**：默认/沉浸档中，本来就放得下的意群内部是**不可达切点**；
   频繁档才允许为了短视频节奏切进意群。

在满足硬约束后，用动态规划最小化代价：目标字数偏离、过短/过快惩罚、标点奖励、
跨句段合并成本。四个档位只是参数不同：

| 档位 | 目标/上限字数 | 最短停留 | 最长停留 | CPS 上限 | 保护意群 |
|---|---|---:|---:|---:|---|
| 默认 | 15 / 24 | 0.9s | 6s | 9 | 是 |
| 频繁 | 10 / 15 | 0.75s | 4.5s | 10 | 否 |
| 沉浸 | 20 / 30 | 1.3s | 7s | 9 | 是 |
| 按标点 | 不控制 | 0.02s | — | — | 纯标点直断 |

## 工作原理

1. 文件先经百炼"临时上传"接口存入官方临时 OSS（48 小时有效，文件与模型绑定）
2. 提交异步录音文件识别任务（REST，`X-DashScope-OssResourceResolve: enable`，开启词级时间戳）
3. 轮询任务，取回句级+词级时间戳分段，登记为资产 `assets/segments/{id}_{名}.json`
4. 导出时选择一个场景档位（`app/export_split.py` 只做分发）：
   - `split_punct.py`：按标点直断；
   - `split_presets.py`：默认/频繁/沉浸共用同一套确定性 DP 排版引擎。
   `app/tokenize.py` 负责把 ASR 词序列对齐成不可再分的 token，`app/split_base.py` 负责组装时间轴。
   一条字幕 = 一个 token 区间，于是“不切词 / 文本无损 / 时间精确 / 时间不重叠”是**结构保证**，
   而不是靠事后断言追补。
5. **任务只在内存里，不跨重启恢复；真正持久的是 `assets/`。** 服务重启只重建资产索引
   （音频 / 识别结果 / 字幕），所以"磁盘上有结果、内存里没任务"不会造成数据丢失。

注意：`fun-asr` 使用 `input.file_urls` 数组，结果在 `output.results[]`；
词级时间戳固定开启，不需要额外传 `enable_words`。

## 目录结构

```
app/            FastAPI 后端
  config.py         配置、模型注册表、四档断句配置
  dashscope_client  百炼 REST 客户端（临时上传 / 异步转写 / 轮询）
  tokenize.py       【地基】token 化：O(n) 对齐、碎片合并、成对符号回收
  split_base.py     【地基】把切分结果组装成带时间戳的字幕条
  split_punct.py    【档位】按标点：保留 ASR 标点直断
  split_presets.py  【引擎】默认/频繁/沉浸：同一套约束与 DP，只换目标参数
  export_split.py   门面：按档位分发，不放断句逻辑
  jobs.py           识别与导出任务（内存态，不跨重启恢复；已完结任务会剪枝）
  assets.py         资产库：音频 / 识别结果 / 字幕的登记、索引与链条
  srt.py            SRT 生成与解析
  main.py           路由 + 只服务本机的访问控制
static/         Web 页面（原生 HTML/JS，含导出面板）
scripts/        转写、冒烟测试、模型评测、断句离线验证、待删文件归集（to_trash.py）
tests/          无头端到端测试（mock 百炼接口，不耗 API）+ 手工联网检查脚本
assets/         资产库：音频 / 识别结果 / 字幕 + index.json（运行期生成，不进版本库）
uploads/        上传暂存区：文件一旦落盘就移入 assets/，正常不留东西
results/        评测与冒烟测试的产物（results/eval、results/clips）；导出不再写这里
samples/        手工留的识别结果样本（运行期自定义，不进版本库）
```

## 测试

```powershell
pytest tests/ -v                  # 无头端到端测试（推荐；用例数随本地普通话样本增减）
python tests/test_api.py          # 等价入口，内部转发给 pytest
python scripts/regress_export.py  # 断句引擎离线验证（自动发现转写数据，零 API 成本）
python scripts/smoke_test.py      # 用 2 分钟真实音频验证识别链路（默认 fun-asr 模型）
python scripts/evaluate.py        # 用测试音频/ 下的素材评测 Fun-ASR（默认取前 15 分钟）
python tests/live_http_check.py   # 对运行中的服务跑一次真实链路（需先跑 smoke_test.py）
python scripts/transcribe.py "测试音频/可能是最AI的AI PC平台？NVIDIA RTX Spark PC技术解析！.m4a"
```

测试用 pytest 组织，每个用例通过 fixture 拿到干净的全局状态（百炼 mock、任务表、
资产库、上传目录），可单独重跑、乱序跑、并行跑。`tests/test_api.py` 会在
真实识别结果上校验四档的结构不变量：文本无损、不超档位上限、时间单调不重叠、断点都在 token 边界。
样本按目录自动发现（`samples/`、`assets/segments/`、`results/preset_eval/segments/`），
找不到时用例 skip，不会静默变成“零个用例”。

本轮用 5 份不同类型普通话素材（数码评测、体育解说、烹饪、人物评论、健康科普）加 6 份历史素材做了鲁棒性回归：
默认档平均 14.8 字、P95 22 字；频繁档平均 10.3 字、P95 14.5 字；
沉浸档平均 18.8 字、P95 27 字。三档文本均无损、无超限、无时间重叠。
